# Repository and evaluation review, 7 September 2026

This pass adds optional compact retrieval and corrects defects in persistence, source boundaries, and agent integration. It does not establish general product superiority.

## Scope and evidence

The baseline is `33c5acd3cba2db192d0a3f6329e8d2e4383f4048`. Changes remain on the isolated branch `codex/muninn-eval-context-pass`. The review covers the module inventory, available evaluation artifacts, packaging contracts, and selected failure paths. Regression tests reproduce the defects before their fixes.

## Implemented changes

| Area | Previous failure | Current behavior |
|---|---|---|
| Memory packs | Prefix truncation could omit late evidence. Output overhead could exceed the estimated budget. | Optional complete-block excerpts include source references. All pack formats account for rendered overhead. |
| Delivery accounting | Selected notes could receive recall events even when they did not fit. | Recall events identify only delivered results, including compact recovery references. |
| Ledger synchronization | A remote fetch could overlap a local append that the later merge overwrote. | A bounded lock protects the final union with current local events. Network operations remain outside the lock. |
| Derived caches | Writers shared a temporary filename. A live writer could retain state from a replaced ledger. | Writers use separate temporary files. Ledger identity invalidates stale caches after replacement. |
| Journals | Stale bundle objects could overwrite episodes or compiled state. Numeric suffixes sorted incorrectly after nine collisions. | A journal lock and disk checks preserve episodes. Numeric suffixes determine same-time order. |
| Transcript import | A generated title could retain a secret or truncate it before scrubbing. | Summary text is scrubbed before truncation. Final imported text is scrubbed as well. |
| Source freshness | Git-ignored files entered the index, but their changes did not refresh it. | Snapshot detection includes the same eligible source inventory. |
| Source boundaries | Directory traversal could follow file symlinks or read a named pipe. | Directory extraction and source indexing reject these file entries. Explicit file inputs retain their separate contract. |
| Instruction updates | Nested or duplicate managed markers could remove unmanaged content. | Updates require one ordered marker pair and reject ambiguous content. |
| Agent hooks | Session-end review could select another session. Codex startup fields appeared at the wrong schema level. | Review uses the supplied session identifier. Codex metadata belongs to the command handler. |
| Feedback identity | Missing session identifiers became separate timestamp identities. | Only explicit caller identifiers establish cross-session evidence. Unknown feedback remains recorded. |
| Gap scope | A relative path from one repository could trigger extraction from another. | Root digests scope new gap observations. Historical unscoped gaps cannot trigger extraction. |
| Evaluation reporting | SWE-bench headlines contained fixed counts that could contradict new results. | The analyzer derives metrics and narrative counts from case-level rows. |

The standard-library core remains unchanged as a dependency policy. The [pack guide](CONTEXT-PACKS.md) defines excerpt limits and exact-source recovery. The new format does not automatically collect transcripts, create accounts, or change installed agent configuration.

## Evaluation audit

The saved SWE-bench archives retain valid digests. All 1,500 condition-level metric sets reproduce from their rankings across 300 cases. The regenerated report uses those saved rows. It is not a fresh retrieval run against downloaded repositories.

All five LongMemEval reports match their saved rows. Their small gains and negative semantic-seed result remain visible. The permissive historical judge parser did not change saved labels, but future evaluations need strict structured scoring.

The continuity evaluation reproduces 12 of 12 question spans and two of two startup spans. Its additional thread section sits outside the nominal pack budget. These counts measure available evidence, not generated-answer accuracy.

The DependEval aggregate and BrainBench equivalence report cover different tasks. The first measures dependency reconstruction. The second reproduces 555 page-selection decisions. Neither establishes general memory accuracy. Some external corpora and licensed raw artifacts are absent, so this pass cannot independently regenerate every historical result.

The separate context compiler reports 34.52% aggregate proxy-token reduction across seven private prefixes. Only two text-only behavior comparisons were valid. Its 11 evaluator tests pass, but the small sample and omitted tool events prevent a behavior-preservation claim.

The new [paired context evaluation](../eval/RESULTS-context-efficiency-2026-09.md) compares four formats under identical source, query, and budget conditions. Frozen scoring labels remain outside retrieval inputs. Its diagnostic fixtures are development cases, not independent validation. Character estimates and tokenizer measurements require separate interpretation.

## Remaining implementation boundaries

Local locks coordinate cooperating POSIX writers, not distributed writers on arbitrary network filesystems. Source snapshots now perform another metadata scan. On this repository, 15 warm samples increased median snapshot time from 30.22 ms to 33.61 ms. Large repositories need separate measurements.

Scoped gaps do not establish complete repository isolation. Existing resource matching can associate equal relative paths across projects before gap recording. Imported-note source identity needs a separate design and regression suite. No hosted isolation claim follows from this fix.

The feedback correction prevents unsupported future promotions. It does not automatically demote existing learned rules created under the earlier behavior. Harnesses must supply genuine session identifiers through `--session` or `MUNINN_SESSION` when known. Unidentified feedback cannot satisfy the two-session requirement.

Secret scrubbing remains pattern-based. Source metadata checks do not establish adversarial content integrity. The review does not prove removal of every private value or inspect every parser expression.

## Remaining evaluation requirements

1. Pin external datasets before retrieval. The historical SWE-bench runner fetches mutable rows before recording a revision.
2. Isolate model runners from user instructions and tools. Existing Claude runners inherit configuration and use a moving model alias.
3. Verify provider revisions and measure actual calls. The DependEval runner records a fixed Graphify revision and unmeasured zero-call claims.
4. Compare answering systems on identical supported tasks. Use the same model, source split, tool budget, and scoring procedure.
5. Measure complete continuation cost. Include compiler calls, cached input, output, source recovery, retries, and tool schemas.
6. Repeat model runs and scoring. Report paired uncertainty and task-level failures, not only aggregate prompt reduction.

## Context compiler integration

Muninn can supply compact evidence to a separate context compiler without becoming a transcript collector. Both the harness and the agent can invoke the same bounded retrieval operation. A thin skill can specify when retrieval or source recovery is required. It cannot make an unsupported harness invoke itself automatically.

A future compiler adapter needs an explicit input contract for authorized messages and tool events. It must preserve role boundaries, tool-call identifiers, current constraints, corrections, and exact source references. Context-generation identifiers can reset duplicate suppression after compaction. These identifiers do not establish user ownership.

A hosted memory service requires a separate authorization layer. Validated identity claims must map to a canonical account before any memory read or write. The server must enforce account, workspace, and grant boundaries. Model-supplied user identifiers cannot authorize access. This pass does not implement OAuth, hosted storage, or multi-user isolation.
